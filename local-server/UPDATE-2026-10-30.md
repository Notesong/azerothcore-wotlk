## Useful changes in the approved update

- Combat revalidation avoids keeping an iterator across callbacks that can
  alter combat relationships. [Core fix](https://github.com/mod-playerbots/azerothcore-wotlk/commit/e8b5aadf3b9f1485efbba1e6e92d44dcc18f573f)
- Joining a group cleans up its pending invitation, preventing a stale player
  pointer after logout. [Core fix](https://github.com/mod-playerbots/azerothcore-wotlk/commit/39fd1165d9cf7433171bb19739b92d96590d4e55)
- Invalid bot population ranges and zero faction ratios receive safe fallbacks.
  [Population fix](https://github.com/mod-playerbots/mod-playerbots/commit/0875218a72da1eaeaf3d0e376b09dbb3b8a12112)
- Ordinary bots improve loot selection, stalled approaches, interaction
  distances, useful quest loot with nearly full bags and empty-chest backoff.
  [Approach fix](https://github.com/mod-playerbots/mod-playerbots/commit/aa5b17a1ffbb6c6b99d630211dcd45ebc956243c),
  [eligibility fix](https://github.com/mod-playerbots/mod-playerbots/commit/e4236222586aa6f1b032124ed305e78ce9b5421f)
- Ordinary bots running NewRpg can sell surplus goods, buy useful supplies and
  repair at appropriate vendors, retaining quest requirements and needed
  reagents. [Vendor change](https://github.com/mod-playerbots/mod-playerbots/commit/3eb94de72a66bb0ed0877cbe10a1ce01f1fd01a1)
- Ordinary bots refresh their attacker cache when entering combat, reducing
  delayed self-defense. [Reaction fix](https://github.com/mod-playerbots/mod-playerbots/commit/1c6cf8f2c1d8648aab5675610fc7647687540433)

Vesper's headless character uses the separate Presence controller and bridge,
without native PlayerbotAI. Ordinary-bot vendor, loot and reaction changes do
not replace his choices or alter his model instructions. General core fixes can
benefit both Vesper and the ordinary population. Persistent Moon protection and
the existing auction economy are retained in the deployed build.

## Configuration and migration plan

The accompanying behavior example preserves the prior snapshot and adds only
the required reconnect setting and four new module defaults:

```ini
DisconnectToleranceInterval = 60
Playerbots.AutoPickTalentsForPlayerControlledBots = 0
Playerbots.RpgTargetSearchDistance = 150.0
Playerbots.CollectDetailedQuestStats = 0
Playerbots.ProbTeleToQuestGivers = 0
```

Zero is no longer valid for `DisconnectToleranceInterval`; the new minimum is
20 seconds and the normal default is 60. The RPG radius matches the previous
hardcoded default, and the three optional features remain disabled. Existing
PvE, bot population/activity, auction-house and model settings were
preserved. The JSON example is documentation, not a loadable server config.

The approved versions add ten world-content updates and three Playerbots text
updates. The normal startup updaters applied them; all thirteen ledger hashes matched. No new auth or character
schema migration is expected. The update requires rebuilt auth/world binaries
and all installed modules, including the custom Presence bridge.

## Startup follow-up

The desktop Start shortcut now logs Vesper's existing character in after the
world and administration ports are ready. Repeated startup leaves an existing
bridge-owned session connected. It never creates characters or takes over a
client session. An uncertain attach is checked by its original request UUID
rather than resubmitted. A login failure leaves the game services running and
keeps the launcher error visible.

Character login is separate from the Presence model controller. Its saved pause
is preserved; server startup makes no model calls. Offline fake-client checks
cover pending login, uncertain replies, failures and session ownership. Manual
checks confirmed both initial login and repeated startup on the running server.

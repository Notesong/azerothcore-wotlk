## Useful changes and scope

The pair includes the native spell ownership/crash fix and reduced disabled-profiler overhead,
low-level group-buff safeguards, restored instance strategies after relog, improved unique-item roll
handling, food/drink handling, and a missing-creature-template travel crash fix. Core updates cover pet
saving, group-disband loot settlement, lost database transactions, additional quest/raid content,
localization storage and more complete item-recovery records.

These ordinary PlayerbotAI changes do not replace Vesper's Presence/Qwen choices. The custom bridge,
persistent Moon protection, resurrection offers, quest-source fix, taxi receipts, source labels and
normal gameplay rules remain present. All 154 non-overlapping custom files were preserved exactly;
the Player.h merge retained both the custom resurrection state and upstream flight-state additions.

## Configuration and migrations

Only the retired five population-rotation assignments were removed from the existing Playerbots config;
`Playerbots.RandomBotCountMode = 0` explicitly preserves a fixed population. All other 893 existing active
module settings were retained, including 1,000 bots, disabled bot PvP, existing blessing selection,
gear/spec persistence and trainer/talent choices. AHBot and AutoBalance configs were byte-identical.
The independent Windows launchers and saved Presence/model settings were retained.

The normal updaters applied exactly **39 new migrations: 36 world, two characters and one Playerbots**.
All names, hashes and RELEASED receipts matched the source manifest. The locale-column migration
preserved all eight translation sets and the existing English rows; three expected new recovery
messages were added. New recovery-table columns and craft-text rows were verified.

A consistent private cold backup of the entire database directory, configs, binaries/PDBs, Moon and
taxi journals and saved controller settings was verified before installation. Database rollback must
restore this matching set; restoring old binaries alone is insufficient. Both old source pins must
also be restored before starting old binaries, because their updater uses the same source path.
Private backups and settings are not published.
